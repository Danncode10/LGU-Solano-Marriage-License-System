# **PHASE 3 — Software Design**

## 3.1 High-Level Design (HLD)

### Architecture Style
Client-Server architecture with a specialized frontend, a dedicated backend service, and a Backend-as-a-Service (BaaS) for core infrastructure. This can be viewed as a distributed system, leveraging modern web development patterns.

### Major Modules

*   **Frontend (Next.js Application):**
    *   **Applicant Portal:** Facilitates public access to the application form for data submission.
    *   **Employee Dashboard:** Provides an interface for LCR employees to manage applications (search, view, re-upload photos, trigger document generation).
    *   **Admin Panel:** Offers administrative functionalities including employee management (creation/deletion) and system log viewing.

*   **Backend (FastAPI Service):**
    *   Acts as the central API layer, processing requests from the frontend.
    *   Implements core business logic, including data validation (via Pydantic), application status management, and orchestration of the document generation process.
    *   Manages interactions with the Supabase database and storage.

*   **Database (Supabase PostgreSQL):**
    *   Primary data store for all application-related information, employee records, and system logs.
    *   Utilizes PostgreSQL's robust features for data integrity and querying.

*   **Authentication & Authorization (Supabase Auth & RLS):**
    *   Provides secure user authentication for employees and administrators.
    *   Enforces Row Level Security (RLS) within the database to ensure applicants can only access/modify their own data, and employees/admins adhere to their defined roles.

*   **Storage (Supabase Storage):**
    *   Dedicated storage solution for handling and serving applicant photos.

*   **Document Generation Engine (openpyxl):**
    *   A Python-based component within the FastAPI backend responsible for programmatic Excel file manipulation, including loading templates, injecting data, inserting images, and dynamic sheet management.

### Data Flow

1.  **Applicant Intake Workflow:**
    *   An applicant accesses the public-facing application form via the Next.js frontend.
    *   The applicant submits their personal and parental information, which is sent as a POST request to the FastAPI backend.
    *   The FastAPI backend validates the data (Pydantic), checks age constraints, and stores the application details in the Supabase PostgreSQL database.
    *   A unique 6-character code is generated by the backend, associated with the application, and returned to the frontend for display to the applicant.

2.  **Employee Processing Workflow:**
    *   An LCR employee logs into the internal system through the Next.js frontend, authenticated via Supabase Auth.
    *   The employee searches for an application using the unique 6-character code, which triggers a GET request to the FastAPI backend to retrieve application details from Supabase PostgreSQL.
    *   The employee uses the frontend's webcam/phone camera feature to capture a photo of the couple. This photo is then uploaded by the frontend directly to Supabase Storage.
    *   The employee initiates document generation through the frontend, sending a request to the FastAPI backend with the application ID.
    *   The FastAPI backend retrieves all necessary application data from Supabase PostgreSQL and the photo URL from Supabase Storage.
    *   The backend then uses the `openpyxl` engine to process the master Excel template, apply sheet pruning logic (age-based, address-based), inject text data, and embed the captured photo.
    *   The final, generated `.xlsx` document is streamed back to the frontend for the employee to download.

3.  **Admin Management Workflow:**
    *   An administrator logs into the system via the Next.js frontend, authenticated through Supabase Auth.
    *   The administrator accesses the Admin Panel to manage employee accounts (create/delete) or view system logs, sending appropriate requests to the FastAPI backend.
    *   The FastAPI backend performs the requested operations on the Supabase PostgreSQL database (e.g., updating the `users` table) and retrieves log data as needed.

## 3.2 Low-Level Design (LLD)

### Class Structures (Conceptual Examples, e.g., for FastAPI/Python)

*   **`models.py` (Pydantic Models):**
    *   `ApplicantInfo(BaseModel)`: Defines structure for male/female applicant data (name, age, address, parents_info).
    *   `ApplicationCreate(BaseModel)`: Input model for new applications.
    *   `ApplicationDB(ApplicationCreate)`: Database model including `id`, `unique_code`, `photo_url`, `status`, timestamps.
    *   `EmployeeCreate(BaseModel)`, `EmployeeDB(EmployeeCreate)`: Models for employee data.
    *   `AdminUser(BaseModel)`: Model for admin user data.

*   **`services.py` (Business Logic/Service Layer):**
    *   `AuthService`:
        *   `login(email, password)`: Authenticates user via Supabase Auth.
        *   `create_employee(employee_data)`: Registers new employee.
        *   `delete_employee(employee_id)`: Deletes employee record.
    *   `ApplicationService`:
        *   `create_application(applicant_data)`: Stores new application, generates unique code.
        *   `get_application(unique_code)`: Retrieves application details.
        *   `update_photo_url(application_id, photo_url)`: Updates application with photo URL.
    *   `DocumentService`:
        *   `generate_document(application_data)`: Orchestrates document generation steps.

*   **`document_generator.py` (Excel Manipulation Logic):**
    *   `DocumentGenerator` Class:
        *   `__init__(master_template_path)`: Loads the master Excel template.
        *   `prune_sheets(male_age, female_age, male_address, female_address)`: Dynamically removes irrelevant sheets based on business rules.
        *   `inject_data(application_data)`: Maps and inserts textual data into designated cells.
        *   `insert_photo(photo_path, sheet_name, anchor_cell)`: Embeds the captured photo into a specific sheet.
        *   `save_document()`: Returns the modified workbook as a byte stream.

### Database Schema (Supabase PostgreSQL)

*   **`applications` Table:**
    *   `id` (UUID, Primary Key, auto-generated)
    *   `unique_code` (VARCHAR(10), NOT NULL, UNIQUE)
    *   `male_name` (VARCHAR(255), NOT NULL)
    *   `male_age` (INTEGER, NOT NULL)
    *   `male_address` (VARCHAR(255), NOT NULL)
    *   `male_parents_info` (TEXT, NOT NULL)
    *   `female_name` (VARCHAR(255), NOT NULL)
    *   `female_age` (INTEGER, NOT NULL)
    *   `female_address` (VARCHAR(255), NOT NULL)
    *   `female_parents_info` (TEXT, NOT NULL)
    *   `photo_url` (VARCHAR(500))
    *   `status` (VARCHAR(50), DEFAULT 'pending')
    *   `created_at` (TIMESTAMP WITH TIME ZONE, DEFAULT NOW())
    *   `updated_at` (TIMESTAMP WITH TIME ZONE, DEFAULT NOW())

*   **`users` Table (managed by Supabase Auth, additional columns for roles):**
    *   `id` (UUID, Primary Key, from Supabase Auth)
    *   `email` (VARCHAR(255), UNIQUE, from Supabase Auth)
    *   `role` (VARCHAR(50), CHECK (role IN ('admin', 'employee', 'applicant')), DEFAULT 'applicant')
    *   `created_at`, `updated_at` (from Supabase Auth)

### API Endpoints (FastAPI)

*   **Authentication/Authorization:**
    *   `POST /auth/login`: Employee/Admin login. Returns JWT token.
    *   `POST /auth/register/employee`: Admin only. Registers a new employee.

*   **Applications:**
    *   `POST /applications`: Public endpoint for applicants to submit new applications. Requires `ApplicantInfo` payload.
    *   `GET /applications/{unique_code}`: Employee/Admin only. Retrieves details of a specific application. Requires authentication.
    *   `PUT /applications/{application_id}/photo`: Employee only. Updates the photo URL for an application after upload to storage. Requires authentication.

*   **Document Generation:**
    *   `GET /documents/generate/{application_id}`: Employee only. Triggers Excel document generation. Returns `.xlsx` file as a stream. Requires authentication.

*   **Admin Specific:**
    *   `DELETE /admin/employees/{employee_id}`: Admin only. Deletes an employee.
    *   `GET /admin/logs`: Admin only. Retrieves system logs.

# Assumes 'workbook' is an openpyxl Workbook object
# Assumes sheet names like 'CONSENT F', 'ADVICE M&F', etc.

def prune_age_sheets(male_age: int, female_age: int, workbook: openpyxl.workbook.workbook.Workbook):
    sheets_to_remove = []
    
    # Age Constraint R.A. 11596
    if male_age < 18 or female_age < 18:
        # This check should ideally happen at application submission time
        # But as a safeguard, can be handled here during document generation
        raise ValueError("Application invalid: Applicant below 18 years old.")

    # Cases where no consent/advice is needed
    if male_age >= 25 and female_age >= 25:
        sheets_to_remove.extend([
            'CONSENT F', 'CONSENT M', 'CONSENT M&F',
            'ADVICE F', 'ADVICE M', 'ADVICE M&F',
            'ADVICED M-CONSENT F', 'ADVICED F-CONSENT M'
        ])
    # CONSENT F
    elif 18 <= female_age <= 20 and male_age >= 25:
        sheets_to_remove.extend([
            'CONSENT M', 'CONSENT M&F',
            'ADVICE F', 'ADVICE M', 'ADVICE M&F',
            'ADVICED M-CONSENT F', 'ADVICED F-CONSENT M'
        ])
    # CONSENT M
    elif 18 <= male_age <= 20 and female_age >= 25:
        sheets_to_remove.extend([
            'CONSENT F', 'CONSENT M&F',
            'ADVICE F', 'ADVICE M', 'ADVICE M&F',
            'ADVICED M-CONSENT F', 'ADVICED F-CONSENT M'
        ])
    # CONSENT M&F
    elif 18 <= male_age <= 20 and 18 <= female_age <= 20:
        sheets_to_remove.extend([
            'CONSENT F', 'CONSENT M',
            'ADVICE F', 'ADVICE M', 'ADVICE M&F',

            'ADVICED M-CONSENT F', 'ADVICED F-CONSENT M'
        ])
    # ADVICED M-CONSENT F

        sheets_to_remove.extend([
            'CONSENT F', 'CONSENT M', 'CONSENT M&F',
            'ADVICE F', 'ADVICE M', 'ADVICE M&F',

        sheets_to_remove.extend([
            'CONSENT F', 'CONSENT M', 'CONSENT M&F',
            'ADVICE F', 'ADVICE M', 'ADVICE M&F',

            # ...
        }
    }

    for sheet_name, cell_mappings in mappings.items():
        if sheet_name in workbook:
            sheet = workbook[sheet_name]
